## P1：优先修复

### R01. Git 干净安装后无法启动，vendor 构建与运行时依赖不是同一份代码

位置：`package.json:18,25`，`pnpm-workspace.yaml:1`。

`file:vendor/pi-tui` 被 pnpm 安装成包副本；`pnpm build:pi-tui` 只写 `vendor/pi-tui/dist`，Node 却从 `node_modules/.pnpm/.../pi-tui/dist` 导入。干净 Git 快照中没有生成的 dist，因此 README 的 install → build 步骤完成后仍报 `ERR_MODULE_NOT_FOUND`。后续更新 vendor 也可能让测试使用旧副本。

父级复现：`git archive` → 离线冻结锁文件安装成功 → vendor build 成功 → import `src/app.ts` 失败。在隔离副本改为链接到 vendor 后，构建、typecheck 和 App import 均成功。

建议：把 Pi TUI 声明为真正的本地 workspace 包，使用 `workspace:*` 和对应锁文件。不要通过提交 dist 或再维护一份复制脚本掩盖问题。当前副本与 vendor 的运行时源码相同，所以本轮现有测试结果有效；风险在干净安装及未来更新。

### R02. 重复 `--continue` 会恢复上次启动遗留的空会话

位置：`src/app.ts:209-214,786-791`，`runtime/bridge.mjs:1022-1041,1151`。

connect 先创建并持久化一个新会话，再列表/恢复旧会话。这个启动产生的空会话没有删除或复用，下次 continue 就把它当成最近创建的旧会话。

父级原生复现：已有一段真实 fixture 对话 → 第一次 continue 恢复正确 → 第二次 continue 恢复前一次启动生成的空会话，而非原对话。

建议：在创建新 Agent 前用 DSH 原生 session query 决定恢复目标；不要在 TUI 里另造持久化/会话生命周期算法。确有空白会话复用需求时优先使用原生生命周期能力。完整旧日志没有丢失，但用户进入了错误上下文。

### R03. `/resume` 失败会先拆掉当前 Agent，界面仍显示旧会话 ready

位置：`runtime/bridge.mjs:1022-1041`，`src/app.ts:619-640`。

`switchSession` 在验证/打开目标前调用 `closeCurrent`。目标不存在或 preset 挂载失败时，没有回滚；前端也没有收到新 ready/closed。

父级原生复现：`/resume deliberately-missing-session` 后，UI 仍持有旧 session 信息，随后 `state` 返回 `NOT_CONNECTED / NO_SESSION`。

建议：先验证并成功准备目标原生 Agent，再切换/释放旧 handle；失败时保留旧 Agent、编辑器及可用上下文。不要只把 footer 改为 disconnected 来掩盖破坏性的切换。

### R04. 外部 SIGINT 跳过终端恢复

位置：`src/app.ts:200-204,968-982`。

App 仅注册 SIGTERM/SIGHUP。外部 `kill -INT` 走 Node 默认信号退出，不运行 Pi 的 process-exit restore hook。正常 raw Ctrl+C 键事件不受此问题影响。

父级 PTY 复现：inline/fullscreen 均被 SIGINT 结束；信号后的输出没有 cursor-show、paste-off，fullscreen 也没有 alternate-screen-exit。

建议：显式处理 SIGINT；信号退出先恢复终端，再等待有界的 DSH 关闭。保留原生 Agent cancel/flush，不把中断实现成杀模型进程。

### R05. 前端隔离扫描漏掉默认 home patch 和原生 group 的 config 子节点

位置：`src/backend/native-profile.ts:94-105,123-131,176-204`，`src/backend/runtime-home.ts:233-251`。

两个遗漏：不传 `--profile` 时提前返回，完全不检查 home patch；递归访问 `entry.group`，但 DSH 规范是 `group: true`、子节点放在 `config` 数组。

父级原生解析复现：同一 home 中旧 TUI row，无 profile 时 suppressed=0，有 profile 时 suppressed=1；group 内旧 TUI 未被屏蔽，group 内相对插件也只被软链而未实体复制。

影响：旧前端/stdio consumer 可能漏过隔离并争用后端 stdin，或导致启动失败；相对模块也可能回到真实 profile 解析。

建议：所有启动计划都扫描 home patch；用 DSH 已解析的 row 形状统一遍历 `insert` 与 group `config`，不要再造 YAML 解析/合并引擎。

### R06. home 相对插件的源码未热更新，reload 却报告无 pending / 无 restartReason

位置：`src/backend/runtime-home.ts:257-280,353-368`，`runtime/bridge.mjs:520-555`。

home 相对插件被复制到 scratch home，而 DSH 原生 `reconcileProfile` 只比较 profile 目录及其链接包目标内的已加载模块。复制文件成功不等于原生模块被重载。

父级原生对照复现：同样的本地命令插件，修改源码后，profile 相对插件 reload 返回新结果；home 相对插件连续两次 reload 仍运行旧结果，同时 warnings=[]、pending=0、restartReason 缺省。已等待 HMR 初始化及后续 watcher，不是初始化时间差。

建议：让资源位置/解析锚点落入原生支持的模块重载范围；无法做到的外部模块明确报告需重启。不要自行实现 ESM cache 驱逐、模块热替换或第二个插件系统。不能把“配置 reconcile 成功”泛化成“所有插件代码已更新”。

## 可简化点：优先复用 DSH，而非增加框架

1. **模型目录**：`runtime/bridge.mjs:1343-1376` 可消费公开 `@deepseek-ai/dsh-api-session-controller` 的纯函数 `buildModelCatalog(ctx, selection)`，再做 TUI 平铺投影。它已提供 provider failures、reasoning metadata 和默认选择；不用完整挂载 browser SessionController，更不要引入第二模型目录/认证层。现有实现仍是原生注册表的只读投影，不是第二 LLM 客户端。
2. **命令入口**：主 UI 已把 `/compact` 等原样交给 native execute；`onCommand('compact')` 的旧兼容别名可以删除，减少重复拼命令参数的路径。所有业务命令继续保留 DSH 校验和 command/run/done。
3. **Chord 状态**：统一取消、超时和 hint 通知。输入组件、设置 reload、dialog 不应分别维护半套 pending 状态；不要引入另一编辑器。
4. **删除死代码与虚假通用性**：无调用的 `ui/text.ts` 自定义 wrapText/prefixLines/formatDuration/formatTokens；未使用的 NativeProfileApi.resolvePackageDir；PrepareWorkspaceOptions 中未用的 dshPackageJsonPath；永远 true 的 RuntimeWorkspace.owned。只删已证实无用途的接口，不删除 bridge 仍使用的安装 anchor 元数据。
5. **缓存/启动**：CachedBlock 已 fit 的行不必在 TranscriptView 再 fit；找到有效 DSH 安装后不要再执行同步 `npm root -g`。先测收益，不加另一 FPS timer 或 Markdown parser。
6. **决策清理**：`respond` 预删 map 后调用 resolve，绕过 `settleDecision` 的 abort-listener remove。统一在一个结算入口清理/发 closure，避免重复状态与监听遗漏。此项是清理卫生，不把短生命周期 AbortSignal 武断称为永久泄漏。
7. **失败清理**：connect 失败不必走最长的 orderly close 等待；没有 child 的 waitExit 直接结束。`prepareWorkspace` 把 resolveHome 放进 try 或在 mkdtemp 前调用，避免异常时漏目录。
8. **配置事实归 DSH**：relative `../`/外部 file URL 不应在 scratch 被静默重锚定；保留原生解析语义或在启动前明确报不支持。不要为了解决镜像问题写一个自己的插件解析器、安装器或 YAML merge engine。

## 保留的正确设计

- 生产流式与持久流解码使用 DSH BlockAssembler/expandAssistantStream/assembleAssistantStream/surface helpers；没有 Pi AgentSession、第二 model transport、Pi models/auth 导入。
- `/permission` 切换是原生命令，目录只是只读投影；`/plan` 独立，没有伪造通用 mode。
- `/preset` 读取已安装官方 preset 声明并调用原生 resolve/select/mount；空白会话锁定规则与原生一致。effort 来自当前 provider/model reasoning metadata。
- 工具展示读取原生 presentCall/presentResult，不重新执行工具或读文件来猜结果；未观察到结果不冒充成功。
- 单一 Pi Editor 状态，保留 kill ring、undo、history、paste registry；Pi 提供终端差分、Markdown、宽度与公共输入组件。必要的 CC seam 是输入 UX，不是 DSH 业务层。
- 后端独立 fd3，stdout/stderr 不写可见终端。IPC 仍有必要：当前 SDK/ACP 不能完整替代实时增量/决策/取消面，不建议为了减少行数迁移到能力不足的协议。
- append-origin 人类历史与模型 replacement 副本分开；不能为了“合并更积极”让 compaction 副本覆盖人类历史。

## 未确认的覆盖范围与已确认的产品选择

以下不作为已复现 bug 直接修改：

- 可选服务后激活/HMR 替换时，projection 订阅和 capabilities 是否会永久陈旧：代码存在一次性绑定，但尚未用可控服务激活顺序复现。
- Timed user-question 的 wait claim / continued answer 尚未接完整原生 UI 生命周期；需要明确支持边界并使用原生 attachWait/answer，而非自定义超时/重试。
- 自定义插件注册与 UI 内置命令同名时会被 UI 截获；当前官方组合没有同名命令。后续应明确优先级/诊断，而不是悄悄吞掉原生命令。
- 当前 native frame revision 在同 attachment 生命周期内单调，换 Agent 会发新 attachment + reset；不采纳“所有不同 attemptId 都忽略 revision”的改法，会削弱旧流过滤。
- 原生新 assistant settlement 是 append-origin。review 中用 replace-classified 新 settlement 构造的异常不是当前支持版本的实际路径；不因此先删除 surface 过滤规则。

### 本轮用户已确认的后续修复基准

1. Esc/Ctrl+C **保留排队消息**，跟随原生 SessionController。
2. `/model` / `/effort` 使用 **DSH 原生保存默认**。当前 scratch ConfigEditor 的写入不等于真实 profile 持久保存；若没有合适原生 seam，明确报告限制，不自行拼 patch 回写。
3. 允许 **原生 credentials-local 直接使用真实 home 路径**完成正常保存/刷新；TUI 不复制密钥，不自建凭据层，不手工回写。该授权不是本轮已经修改了凭据。
4. 自动标题 **增加 Settings 开关**，不是永久强制开启/关闭。建议未显式设置时继承 DSH profile；切换调用原生插件/配置能力，不由 TUI 自己调用模型生成标题。可能产生的原生模型请求应明确提示。

这些是已记录的修复方向，**业务源码尚未修改，开关尚未实现**。

Pi 式 TUI extensions 热插拔仍是用户明确延期的 TODO，不在这轮 bug 修复建议中扩展范围。
