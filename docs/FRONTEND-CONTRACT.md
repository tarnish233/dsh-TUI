# Frontend contract

Own src/state/, src/ui/, src/demo.ts, test/ui*.test.ts. Parent integrates app and CLI; no manifest/backend/input/shared-helper changes. Use src/backend/types.ts.

## Transcript projection (state)

`src/state/transcript.ts` projects DSH's durable v2 log plus the tentative live stream. It does **not** implement agent semantics and it does **not** reimplement DSH assembly:

- `TranscriptStore` constructor: `new TranscriptStore({ onChange?, codec? } | onChangeCallback)`.
- `setCodec(codec: TranscriptCodec | undefined)`: install `Backend.transcriptCodec`. The parent calls it **before** `reset`/`ready`. `hasCodec` reports whether native helpers are installed.
- `items` read-only view, `info`, `sessionId`, `status`, `hasLiveAttempt`, `reset(info: SessionInfo)`, `clear()`, `handle(event: BackendEvent)`, `report(text, level?: 'info' | 'error')`, assignable `onChange`.
- With a codec: `createStream()` drives the live attempt, `assemble(stream)` drives committed `assistant/attempt` views, `surfaceKind(event)` decides append/replace/none. Without a codec the store keeps attempt identity/ordering/settlements only and shows no streamed preview — there is deliberately no local BlockAssembler/compact-expander mirror.
- Surface semantics: a message event (`user/message`, `assistant/message`, `tool/result`, `system/message`, `developer/message`) classified `replace` is a **model-only** replacement copy. It never appends a transcript item, never overwrites and never erases append-origin human transcript facts, including tool output that native pruning shadowed. Non-surface lifecycle records (`tool/call`, `assistant/attempt`, turn/step markers, `command/*`) are always projected. `sourceEventSeqs` is not written back anywhere.
- Live identity: `attemptId` is identity; every frame carries an increasing `revision`, and `index` only rejects duplicates/stale replays. A committed `stream_end` marks the attempt `committing` until the matching durable settlement replaces it in place; abandonment leaves an explicit tentative `attempt` item.

Item status vocabulary (never a fabricated success/failure):

- `ToolTranscriptItem.status`: `proposed` (model requested the call in an assistant message) → `running` (durable `tool/call`) → `done`/`error` (durable `tool/result`); `unknown` when the turn ended, the connection closed, or a snapshot replay ended before a result. `unknown` never overwrites a real `done`/`error`.
- `AttemptTranscriptItem.status`: `streaming`, `committing`, `abandoned` (durable attempt settlement or explicit abandonment), `unknown` (turn/disconnect before settlement).
- `ToolTranscriptItem.presentation?: JsonRecord`: the ephemeral native view forwarded as `SessionEvent.toolPresentation`. Primary shape `{ call?: ToolCallView, result?: ToolResultView }` from `@deepseek-ai/dsh-tools/presentation`; a flat single native card is also accepted (settled cards are read as results, unsettled ones as call intents). Both halves are merged so a card keeps its pending and completed intent. It is display state only and is never persisted into DSH's log.

## Terminal metadata (renderer-owned)

`src/ui/terminal-integration.ts` adapts the existing native presentation snapshot through the private `#pi-tui` Terminal seam. App supplies `info`, `busy`, `activeCommandIds`, `connected`, `fatal`, pending native decisions and the current child tree; `observe()` sees only authorized native events. This is not a new Agent, queue, title generator or persistence layer.

- Native `turn/end.reason` is turn-outcome authority; `command/done.kind` is only a matched command's outcome. Other command work or a live turn prevents premature completion. `stream_end`, retry, nonfatal errors and local dialogs never imply done/error/blocked.
- OSC 7501 records are complete, cached per transition and bounded to root + 63 children. Current native child work stays separate from root `App.isBusy`; historical cold completions do not notify. Retire old ids before adding replacements. Native `ready` re-arms a halted presenter; old failures and late completion frames are not restored work.
- `SessionInfo.title` / `title` events are native projection facts. Window title uses the native label or workspace fallback; OSC 7 reports the current DSH workspace independently. Saving/restoring titles is best effort: current Rex and matching Ghostty paths ignore the title stack and do not expose the original custom title.
- Automatic notifications defer to Rex Program Activity when native status is on; Ghostty (or Rex status-off fallback) needs positive unfocused evidence before OSC 777. Off disables direct requests only; Always may duplicate native attention. Notification bodies are fixed phrases, not prompts/tool args/error stacks/credentials.
- The same renderer writer emits metadata. Focus/capability/reply parsing belongs to ProcessTerminal's one input pipeline; there is no raw stdin reader, production Rex CLI/socket client, notification daemon or automatic mux passthrough. Pause/dispose/exit release owned metadata and modes before native cleanup.

Public integration and user limits: [contract](TERMINAL-INTEGRATION-CONTRACT.md), [terminal guide](TERMINALS.md), [research](TERMINAL-RESEARCH.zh-CN.md).

## Rendering (ui)

- `src/ui/transcript.ts`: `TranscriptView` implementing `Component`, constructor `(store, options: { showThinking: boolean, expandTools: boolean })`. Options stay mutable by the parent. One cached component per stable item id; a token only invalidates the live item.
- `src/ui/blocks.ts`: tool cards prefer the native render intent — terminal (command/cwd/description, output, exit code/signal), diff (pending "proposed, not applied" vs completed "Updated … with N additions and M removals"), read (native absolute line numbers), search (files/paths with `truncated`/`total`), web (sources or fetch status) — and fall back to the generic name+argument summary plus opaque `tool/result` `meta.diffs` when no card is forwarded. FileDiff carries a hunk, not file coordinates: hunk rows keep CC add/delete colors but show **no** absolute line numbers, and a pending call never claims a file effect.
- `src/ui/theme.ts`: `editorTheme`, `markdownTheme` and small styling functions; no Pi Agent dependencies.
- Notice plane: there is exactly one, `store.report(text, level)`. The caller's `level` — never the text — decides presentation: `error` is `● <headline>` in error red with every following line indented under the marker, `info` is a muted `· …` line. Multi-line native text (including a bounded redacted `Native cause: …` line a backend may append to a *correlated* compact failure) is rendered verbatim and wrapped width-safely, so the UI never summarizes, truncates, relabels or re-splits it, and never invents a cause. A notice is not durable session truth: it is appended after any tentative live item and never settles or rewrites it. `src/ui/text.ts#sanitize` strips terminal sequences and C0/C1/DEL bytes before any notice, tool or dialog row is styled, so untrusted provider text cannot paint the screen.
- `src/ui/dialogs.ts`: `SelectDialog(tui, {title,items:DecisionOption[],onSelect,onCancel})` and `DecisionDialog(tui,request,onSubmit,onCancel)`. Both are Focusable Components, expose capturesViewportInput where appropriate, Ctrl+P/N navigate via injected global keybindings, printable custom answers edit rather than trigger j/k selection. `DecisionDialog` returns the opaque option value or `{answers:(string|string[])[]}` per backend contract.

## Shared modal surfaces

Every user-facing popup uses `src/ui/modal.ts`; it owns chrome and geometry only, never an editor, native request, history or terminal writer.

```ts
const frame = new ModalFrame()
const geometry = frame.measure(width, options)   // bodyWidth/bodyHeight/bodyRow/bodyCol
const lines = frame.render(width, bodyLines, options)
frame.bodyMouse(event)                            // translated body-local x/y/width/height
frame.handleMouse(event)                          // chrome only: close/action chips
frame.invalidate()
```

- `ModalFrameOptions`: `title`, optional `subtitle`/`before`/`after`, actions, `onClose`, `maxHeight`, `keymap`, and optional `ownerKey` identifying the selected native item. `ModalAction.action` is a keymap action id; the footer prints its effective binding, omits a fake key when disabled/unbound, but keeps a real clickable capability. Disabled actions paint no click.
- Sizing: `modalOverlayOptions(size)` and `modalHeight(tui, size)` use the same bounded height; `compact` is for short choosers, `standard` for Settings/agents/session/model/help/decisions, `wide` for Tools/Image/Child. Normal terminals reserve a few rows so the native status/footer stay visible; tiny terminals drop chrome then footer details rather than emitting an unusable empty box.
- Geometry is measured before the body is built; components render exactly `bodyWidth × bodyHeight`. Ordinary body text must already be width-safe/sanitized. Native image APC/iTerm lines are passed through raw; the frame must not treat them as text, wrap them, or truncate their payload. There is no rgba backdrop support in the public overlay API, so the surface is opaque.
- Mouse: hidden/clipped actions get no hitbox. Body hitboxes use `frame.bodyMouse`. A press is pinned by `ownerKey` + target id; motion/drag, invalidation, target change or a row disappearing voids the click. A press on chrome never becomes a body action and vice versa.
- List surfaces: `src/ui/modal-list.ts` is the shared body layer for list-style modals (Settings and Keyboard shortcuts use it). `windowList(blocks, budget, {start?, center?})` paints the visible grouped-row window and returns the matching `HitRange`s (painted row ranges plus stable row keys/indexes), so hit testing can never point at a clipped row; `center` keeps a short value picker's focused row visible and `start` restores a captured scroll offset. `ModalListSurface` owns the measure → build-to-inner-size → content-shrink → header/status/footer render pipeline, `bodyMouse`/`beforeIndex` translation and the one `rowMouse` press/click policy (press pinned by row key + owner key with `render:false`, plain click still resolves the painted row, chrome stays chrome). Components keep their own selection, mode machine, row rendering and actions; this is a helper, not a second component framework. Modal lists use `HitRange`/`bodyHitAt`; `HitboxRegistry` remains the transcript/tool/thinking layer (persistent hover, child dispatch) and must not be instantiated just to get list click pinning.
- Settings is one continuous grouped page, not category tabs: all available rows share one viewport in General/Thinking/Tools & Diff/Agents/Images/DSH/Keyboard order. `getVisibleRows()`/`rows()` return the whole roster with an empty query and cross-section matches with a query; `allRows` ignores the query. Up/Down crosses group boundaries; existing `settings.previous-category`/`next-category` IDs now jump sections (Left/Shift+Tab, Right/Tab) without filtering, clearing search, saving or running native commands. Group headings and blank body cells are inert. One frame shares one parent-native metadata projection; invisible presses do not repaint. Framed paste is ignored by non-text list/picker surfaces using the existing `BracketedPasteFilter`; an unfinished paste keeps its input owner across mouse gestures.
- Parent hosting: `App.showDialog` mounts the component with `tui.showOverlay(...)` while the one `Prompt` remains mounted in the slot. The modal owns focus; closing restores the same Editor. Do not call `handle.hide()` for temporary hiding inside a modal. Overlay lifecycle still increments `surfaceGeneration` and retires stale async callbacks.
- Restore/feedback: Settings exports `SettingsViewState` (`captureView` / `initialState`); Agents exports `AgentsViewState`. Parent returns to the previous Settings section/row/query/scroll position (`SettingsViewState.category` is positional metadata, never a page filter) or Agents list state, and calls `setMessage(text, error?)` for native failures that must stay visible in the active surface. `ModalFrame` has no hidden state or timer.
- Input: popups use the shared keymap contexts from `src/input` (`modalList`, `modalSearch`, `settingsList`, `keybindingsList`, `queueList`, plus `toolDetails`/`imageDetails`/`subagent*`). Search fields reuse `InlineAnswer`/`CcEditor`; browse-mode printable keys are inert. No component adds a raw stdin listener, second editor or hardcoded shortcut label.
- Help search is on-demand (`modal.search`, Ctrl+F by default); opening Help alone never starts filtering or execution. Session scope toggle is `session.scope.toggle` (Ctrl+A), not Tab. Image preview toggle is `image.details.toggle-preview` (`p`).

## Resume session picker (ordering)

`src/ui/session-picker.ts` (`SessionPickerDialog`) is presentation only.

- **Ordering policy.** Rows are painted in exactly the order of the incoming `sessions` DTO listing (DSH's newest-first display order). The component never re-sorts, never `stat`s or opens a durable session artifact, and never selects a session on its own: recovery is explicit (`--resume <id>`, `/resume <id>` or one user selection) and there is no newest-session auto-selection. The only allowed re-order is fuzzy relevance inside an active query (`fuzzyFilter` over title+cwd); clearing the query restores the native order exactly, and scope switching only adds or removes rows.
- **Display stamp.** `SessionPickerItem.createdAt` is the display-only native header creation stamp used by the age column. It is never an ordering input; an absent/zero stamp renders `unknown time` in the row's listed position. A TUI-owned mtime scan would be a second durability truth and stays out of both adapter and frontend.
- **Two-phase data.** `loading` + `setSessions` (headers, `titles:false`) + `setTitles` (lazy titles for `onVisibleIds` rows only) keep the dialog openable immediately; title enrichment never re-orders rows and never reads a session file. `setSessions` is repeatable, keeps the selected session id, and falls back to the first listed row when that id vanished.
- **UX kept.** Search/readline field, Current Folder ↔ All scope (registry binding, remappable/disable-able), lazy titles, phase-1 loading, per-scope/query empty states, honest untitled rows, mouse press+click pinned by the selected native id, and width-safe rendering at any width ≥ 4 with no stdout writes.

## Read-only skills metadata (help)

`src/ui/help.ts` stays the read-only help surface; the only addition is `HelpPanelOptions.skills?: SkillCatalogSnapshot`, a **type-only** import of the neutral `src/backend/types.ts` contract. The parent fetches the snapshot through its backend seam; this component never queries, caches or mutates it.

- Omitting the option (or passing `undefined`) renders exactly the historical Commands / Custom commands body — no heading, separator, count or empty sentence — and every existing read/write/height/scroll/chord/close semantic is byte-for-byte unchanged.
- When supplied, one **full-width** `Skills` section follows the two columns (after the stacked sections on narrow terminals). Rows are display metadata only: the literal native `/name`, the sanitized description (at most three wrapped rows, ellipsized), an optional `when: …` `whenToUse` line (at most two wrapped rows, ellipsized) and a `[user-only]` marker for `modelInvocable: false`. No skill body is read, there is no second Editor, timer, chip or sidebar, and Enter/digits/printables/click never execute, select or fill the prompt. Names/descriptions are sanitized and width-safe for CJK/emoji/ANSI, and the body stays inside the shared dialog row budget and scroll keys.
- Availability is honest. `available: false` prints `Skills ?` and explains that no native metadata observation can currently be read; it does not assume an Agent must exist or a model `skill` schema must be visible. DSH's public preset scope lease can serve startup discovery without an Agent. Entries from unavailable views are not painted, and no redundant `incomplete` marker is added. `complete: false` adds an `incomplete` heading marker and, without entries, "Catalog incomplete… is not proof this session has none." Only `available && complete && entries.length === 0` renders `No user-invocable skills.` The App always supplies an observation (unavailable when the capability is absent), so the Skills section cannot silently disappear; omitted-option invariance remains the component-level contract.

## Subagent surfaces

See `docs/SUBAGENTS.md` for the full contract.

- `src/state/subagents.ts`: pure `SubagentProjection` fold of `subagents` snapshots and `subagent` upserts; `composeSubagentRows` anchors one stable transcript row per **direct** child only when `parentSessionId` matches and `catalogSeq` is trustworthy; unsequenced/nested/external cold rows stay overlay-only. `readSubagentMessage` projects durable `user/message` sources `subagent-settled` / `agent-message` with exact seq/sender/summary/text. `buildSubagentTree` is cycle-safe on `parentSessionId`. All of this stays native: grouping is a view over `store.items`, never a stored synthetic fact.
- `TranscriptStore`: `subagentEntries`, `subagentSnapshot`, `subagentsTruncated`, `subagentEntry(id)`; `items` composes anchored subagent rows; `subagents`/`subagent` events are idempotent and session-scoped.
- `TranscriptViewOptions.onSubagentDetails(sessionId)` / `subagentDetailsHint`: **only the visible agent-name text** of an inline subagent row, a grouped member row or a durable trigger sender is a link (bold + brand blue + underline, brighter on hover). Guide/glyph/status/metrics/attribution/body/padding stay selectable plain text; a non-openable child, a missing callback or a clipped-away name owns no hitbox. Label paint is sanitized and `oneLine`-flattened (LF/CR/TAB safe) while the store keeps the exact native label. `TranscriptView` syncs `subagentEntries` from the store so a trigger sender shows its real label (and link) only when the catalog already knows the child; otherwise the durable id is painted as honest plain text.
- `src/ui/subagent-link.ts`: `SubagentLinkHitboxes`, the narrow gesture helper behind every transcript subagent name link (individual row, grouped collapsed/expanded member, trigger sender). Only a left press on a visible link claims; every other press is an outside-press tombstone, `move`/`drag` are never claimed (hover still repaints), a click is accepted only for the claimed region with unchanged identity/coordinates, and a region that disappears expires the gesture for good. Not a `HitboxRegistry` rewrite: Tools/Thinking keep their existing semantics.
- `src/ui/subagent-group.ts`: `planSubagentGroupNodes` folds **consecutive** `subagent` catalog rows and `subagent-message` facts into one `SubagentGroupBlock` (minimum two; any user/assistant/tool/attempt/notice/todo item or tool group breaks the run). Collapsed rows keep the summary and fold message bodies; expanded members are the real member blocks behind a two-column guide whose width is the single source for `childWidth` and the dispatched mouse `xOffset`. Disclosure reuses the ephemeral Tools map (`group:<anchor item id>`), so `Ctrl+O` and single-expand behave like tool groups; the header toggles only and can never open a child, and expanded bodies carry no hitbox. `groupTools: false` restores one row per record — no new setting/shortcut. Rows have no accordion and no per-run metrics; continuable completion reads `last run completed · idle`.
- `src/ui/agents-overlay.ts`: temporary `AgentsOverlay` modal with `setEntries`/`setSnapshot`/`setEntry`/`update`/`dispose`, `subagentList` key context, `parentSessionId` tree, native session-total tokens/timing, external leaves, mouse/wheel and width-safe degradation; no pane or timer. Optional `onReply`/`onStop` plus pure `subagentCanReply`/`subagentCanStop` gate configurable R/S actions and pinned mouse chips; the component emits intent but never mutates a child.
- `src/ui/child-session-view.ts`: `ChildSessionView` frames a parent-supplied child `TranscriptStore` + `TranscriptView` with `subagentSession` input: read-only conversation, breadcrumb/status/model/session totals, Esc close, global `app.exit` delegated via `onGlobalAction`, no composer/timer. Reply requests the parent's one main Editor; Stop only targets active local rows; external tasks have no local transcript or controls. `loading?: boolean` (default false) plus `setLoading(loading)` show the narrow loading shell described below; they never fabricate a `SessionInfo`, add an editor, or close/stop anything.
- `src/ui/subagent-progress.ts`: `SubagentProgress` is the compact **active-only** progress tree the parent mounts immediately **before** the one Editor/slot (never inside the transcript scroll host). Visual shape follows the installed pi-subagents `aboveEditor` widget (`src/ui/agent-widget.ts`, MIT): dim `├─`/`└─` guide, small live marker, **bold** label, muted inline state/metrics, one indented `⎿` activity line per live child, `+N more (…)` overflow. Only DSH facts are painted: native label, `one-shot`/`continuable`/`unknown mode`, native status (`running`/`initializing` here), optional `provider/model · effort` route, session-total tokens/time and the real current `lastActivity` of a `running` child. Pi's turn counter, tool-use count, context percentage and cost have no DSH equivalent and are never synthesized; no transcript is fetched to fill the activity line.

  ```ts
  const progress = new SubagentProgress({
    keymap, onOpenAgents, onOpenChild, onRenderRequest,
    maxRows: () => rowBudget(),
    mouseBlocked: () => dialogOpen || overlayOpen,
  })
  progress.entries = store.subagentEntries   // full native catalog; filtered to active here
  progress.truncated = store.subagentsTruncated
  progress.replyTargetId = target?.childId   // a priority hint among active rows only
  progress.spinnerFrame = workingGlyph       // parent's existing Working clock; optional
  // Static hosts may instead assign progress.maxRows / progress.mouseBlocked.
  progress.render(width); progress.invalidate(); progress.handleMouse(event); progress.dispose()
  ```

  - `spinnerFrame` is **presentation input only**: the parent assigns the raw one-cell Working glyph (`· ✻ ✶ ✳`, the same sequence as its editor status) from its own existing clock before each paint, and only native `running`/`initializing` rows use it. The component owns no timer, animates nothing historical, and falls back to the static native `⏺` for an empty/multi-cell/control-bearing value (sanitized first, so it cannot widen a row or shift name columns). Assignment never triggers a render or resets a hitbox; leaving it `undefined` keeps the static marker.

  - **Active-only:** only entries whose native status is `running`/`initializing` get a row. A child retires on the same native catalog update that settles it; the component keeps no memory, turn age or timer, never mutates `entries`, and a settled reply target is not resurrected (the main Editor states that destination). All settled children and external leaves stay in `store.subagentEntries` and are reached through the Agents overlay / `/agent`.
  - `maxRows` is a **hard total** (header, rows, per-row activity, overflow count and the trailing separator). A constructor value may be a live getter/callback (re-sampled on every paint for resize/multiline budgets); an explicit assignment wins, otherwise the constructor option, otherwise the last number. Default 8. Non-positive budgets render `[]`; non-finite values fall back to 8.
  - App uses a live `mouseBlocked` getter: closing an overlay only requests a Pi repaint, so mouse affordances must immediately become available again without waiting for typing or another native event.
  - An empty catalog, and equally an all-settled/truncated one, renders `[]`: no header, blank spacer or invisible hitbox. Nothing is read from the backend, no timer runs, no polling, no child work.
  - Priority: the reply target first when it is active (marked, label in the accent tier), then every other active child **with** its activity line, in native catalog order. The overflow count (`+N more (…)`, grouped by raw native status) is reserved before extra rows and counts only active children; retired history is never folded in. A live row degrades to its summary line only when the budget cannot hold the pair.
  - Header `● Agents · N children · <chord> open` counts the active children painted here (the marker stays in the accent tier because the widget only exists while something is live; the actionable `Agents` word remains a blue underlined link; `incomplete` when the native catalog is truncated). The chord comes from the real keymap in the editor context, so a remapped action advertises the new key and a disabled one advertises nothing.
  - Loading shell (`ChildSessionView`): `loading?: boolean` + `setLoading(false)` on the same `ChildSessionView`; while `true` the body is exactly `Loading child session…` (compact viewports included), scrolling is inert, and the normal header/identity/footer, Reply/Stop gating, Esc/global actions and hitbox rules are unchanged. Turning it off after the parent resets the child store from the native snapshot paints the read-only conversation. No fake `SessionInfo`, second Editor, timer, model or child mutation.
  - Mouse is the only input: **only the `Agents` word / `+N more` text** request `onOpenAgents`, and **only a visible openable agent-name span** requests `onOpenChild(entry)`. Internal links are bold + brand blue + underline, brighter on hover; no OSC8/browser/custom-scheme URL is emitted. External, remote, missing-callback and clipped-away names have no fake link/hitbox. Spans are measured from final painted/clipped display columns (CJK/emoji/ANSI safe), not string lengths. Guide/glyph/gaps/counts/chords/status/timing/tokens/route/activity/padding stay non-navigation text.
  - Non-link presses and every move/drag stay unclaimed: native selection and copy-on-select work after a hovered link and across link boundaries. An outside-press tombstone survives reflow/invalidate/temporary blocking, so a name that later moves under its coordinates cannot receive that click. Claimed name presses are pinned by id; vanish/reappearance, invalidate and blocking void them; dragging never becomes a click jump. `mouseBlocked` removes hits and never captures input. The component never takes focus or installs an input listener; the Editor keeps ordinary typing and `r`/`s` stay text.

## Demo (offline only)

- `src/demo.ts`: `DemoBackend({cwd?:string,delayMs?:number}?) implements Backend`, explicitly demo-only and never a fallback for a failed real connection. Deterministic real-shaped DSH live frames with strictly increasing revisions + durable v2 session events, every surface event carrying `surfaceOp: 'append'`, plus questions, tool call/result, abort, error and unresolved-tool fixtures.
- `transcriptCodec` is exposed **before** `ready` and is a clearly fixture-only implementation (`DemoTranscriptCodec`) so `--demo` and pure UI tests run without DSH installed. It is not a production mirror and must not be used when a real backend is present.
- Commands: `command('commands')` returns native-shaped `CommandDescriptor[]` (`{name,description,input?}`); `command('execute', {line})` returns `CommandExecution` (`{commandId,result:{kind,text?,sourceEventSeq?}}`) and appends paired durable `command/run`/`command/done` records. `command('compact')` is a compatibility alias for the execute path, not its own compaction implementation.
- `subagent` keyword fixture: parallel direct children (running/completed/failed), one nested child, one external leaf, a durable settlement notice and adjacent-Agent trigger, a full catalog snapshot plus a live reactivation upsert. `command('subagent-session', {sessionId})` returns a deterministic child `SessionInfo`; external ids fail. `command('subagent-follow', {sessionId, follow})` is a fixture no-op (`following:false`, `supported:false`). Fixture-only `subagent-prompt` preserves text/image content and queue/steer, appends durable child facts and settles continuable work to `idle`; `subagent-interrupt` projects an active local row as `stopped` with `lastStopReason:'aborted'`. Fixture-only, no model/network.
- `subagent-many` keyword fixture: the same `subagent` scenario plus three deterministic **local continuable running** rows (`demo-child-active-1..3`, distinct labels and current activity, no `catalogSeq`, no fabricated session totals/timing) emitted as native-shaped `subagent` upserts and included in the final snapshot. It is the explicit offline CLI fixture for active-only progress overflow (`+N more`), and their `subagent-session` reads work like any other fixture child. No Agent, model, backend runtime or production flag is involved; the default `subagent` fixture is unchanged.
- `skills` keyword / `--demo skills`: `command('skills')` returns the frozen fixture `DEMO_SKILL_CATALOG` — `available: true`, `complete: true`, entries `code-review`/`changelog` (model-invocable), `release-notes` (`modelInvocable: false`, user-only) and `compact`, which deliberately reuses a mounted native command name so the parent's `/name` collision routing has a real fixture. `SessionInfo.capabilities` advertises `'skills'` because this backend really implements that query (fixture advertisement, not a production `/skills` command or a native skill engine). An entry only ever carries `name`/`description`/`whenToUse?`/`modelInvocable`: no body, path, injection payload or execution stand-in, and the snapshot cannot be mutated into a second catalog. Sending `skills` or a fixture `/name` streams one metadata-only "Offline skill fixture" acknowledgement (no tool, decision, model, injected skill body or native command change); mounted command execution and every other demo path are untouched.

The parent implements the prompt wrapper, working/status/footer, key action routing, history search, native codec loading/wiring, CLI and shutdown. Tests use @xterm/headless or pure state assertions, no model calls and no DSH runtime imports from UI/state. Preserve attribution for copied helpers.
