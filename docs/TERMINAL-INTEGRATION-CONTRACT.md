## Ownership and invariants

- Native DSH owns root/child Sessions, model transport, tools, permissions, questions, commands and durable outcomes. Terminal integration is a renderer-owned presentation adapter, not another harness.
- Reuse the existing private `#pi-tui` `Terminal.setProgramStatus()` and `ProcessTerminal` OSC 7501 query/DA-sentinel input path. No second stdin consumer, Rex socket client, production `rex` subprocess, provider/config imports, credential access, auto title generation, guessed percentages or transcript scraping.
- Existing extensive uncommitted work is the baseline. No commit/publish/install/global config changes. Offline tests use private homes/workspaces; actual terminal acceptance uses newly created, owned fixtures only.

## Protocol behavior

1. OSC 7501 rev 0.4 is generic. Root record: `app=terminal` on Rex (the explicitly accepted neutral icon/activity grouping), `app=dsh-tui` elsewhere; states `idle`, `working`, `blocked` (`permission`/`question` only when DSH requests it), `done`, `error`; `clear` at terminal handoff/exit. Each report is complete. Negotiate any supporting terminal, not just Rex; respect `PI_PROGRAM_STATUS` overrides. Advertised state/kind subsets must not turn an unavailable state into false success.
2. Native child catalog entries may be represented as bounded hierarchical records with stable safe ids and native labels. No UI modal gets a blocked record merely by opening. Unknown/external/cold records must not pretend they are live work. Clearing a parent clears descendants; restart must replay only currently valid records.
3. Busy is native running or mounted native command work. Tentative stream end, retry, warning or arbitrary UI notice is NOT completion. Only accepted live durable `turn/end` facts can report turn completion/failure; cancellation reports idle. Matched native `command/done.kind` can report a distinct Command complete/failed outcome, never a turn settlement. App's existing active command ids prevent premature completion when a small presentation correlation cache is incomplete. Current session/attachment changes clear prior outcomes and records. Historical restored turn/end facts do not produce notifications.
4. OSC 0 title consumes native session title when available, with application/workspace fallback; no local title model/override. OSC 7 reports current native workspace as an encoded file URL, not the contents of prompts/tools. Save/restore window titles through supported terminal stack operations; document emulators that ignore them. The Rex title prefix is only static `🐳`; the user removed the preceding star/work glyphs. No `animationStep`, work frames or title-only Reduced-motion branch remains. The title honors `terminalTitle` and never changes merely because native work state or UI ticks change. Other terminal families retain plain native/fallback titles. This is text, not the SVG/PNG app artwork or a native icon registration.
5. Ghostty/Rex support OSC 777 desktop notifications; automatic policy uses exact terminal focus reports (CSI I/O) and sends only on transitions into newly blocked, completed or failed work. When native rich-status presentation is available and reporting is enabled (Rex), auto suppresses explicit notifications to honor the terminal's Program Activity policy. If native reporting is disabled, Rex can use the focus-safe OSC 777 fallback instead. Ghostty may parse protocol definitions in its library without implementing them in its GUI; keep its focus-based notification/progress fallback independent. Always is an explicit forced-notification opt-in and may duplicate terminal-owned attention. Notification messages are generic, bounded and privacy-safe: never prompt, tool args, raw native errors, credentials or full answer text. Terminal/OS permission and rate limits remain terminal-owned. Do not generate heartbeat notifications; deduplicate across repeated frames/snapshots and avoid progress/notification interference.
6. Legacy OSC 9;4 is an indeterminate fallback only; no invented percent. Stop unnecessary repeated frame writes/heartbeat after OSC 7501 is confirmed on terminals with rich status presentation so legacy mapping cannot erase richer records. Ghostty can explicitly retain its legacy progress fallback. Existing synchronized frames, keyboard negotiation, images, links and user-triggered clipboard are retained.
7. Focus reports and capability replies are consumed in the existing input pipeline; bracketed paste content cannot impersonate a focus report, key, approval, chord or terminal reply. Pause, external editor, resume, native reload, emergency exit and normal shutdown must restore owned raw/cursor/mouse/paste/focus/status/progress modes. Title-stack save/restore is best effort: current Rex and matching Ghostty paths ignore it and cannot expose the original custom title; do not pretend that limitation is restored successfully. No new metadata writes after ownership is relinquished.

## Preferences

One flat existing settings document, no new profile or terminal configuration subsystem. Add General rows:

- `terminalStatus: boolean` (default true): terminal-native status/progress presentation only.
- `terminalTitle: boolean` (default true): window/tab title presentation only; not DSH auto-title enablement.
- `terminalNotifications: 'auto' | 'off' | 'always'` (default auto): auto notifies only with positive evidence of being unfocused. `always` explicitly opts into transition notifications even when focus is unknown. Off disables explicit notifications, not the terminal's independent display of published status.

The current continuous Settings roster, search, typed edits, resets, sparse persistence, existing row IDs and native read-only rows remain intact. The existing `reducedMotion` preference continues to control ordinary UI animations; terminal titles are static regardless. There is no new icon/animation setting.

## Acceptance gates

- Unit matrix: exact protocol limits, advertised capability subsets, complete-record replacement, root/descendant clear, bounded replay, progress suppression, writer injection, focus/paste/chord isolation, startup/stop/restart/emergency restoration.
- App/VT both renderers: native outcomes/decisions/children/title/workspace, no old-session events, no local picker notifications, generic privacy-safe notifications, preference save/reset/error feedback, no extra backend commands/model prompts caused by navigation/state reporting.
- CLI/PTY both renderers: supported and unsupported negotiation, fragmented replies, focus notifications, cancellation vs completion, resize, Settings and terminal restoration with private homes.
- Real Rex owned fixture: query `program_status`, title/pwd, lifecycle modes and process exit via public CLI. No capture of the user's existing pane or config edits. Notifications are verified as protocol events, not assumed OS permission/popups.
- Ghostty: installed-version and official protocol evidence; attempt owned native GUI fixture if it can be isolated without touching user configuration. Clearly separate actual acceptance from emulated protocol/PTY checks and OS notification permission limits.
- Full build, strict typecheck, complete test suite, whitespace check; retain logs in ignored `.cache/terminal-integration/`.
